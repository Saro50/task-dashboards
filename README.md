# AICodeAgent 任务分期看板

项目价值：希望用同一套短工作流情景，套用于大部份生成，不考虑协作。
 - 帮助用户梳理并完成能并行执行的任务
 - 用 `worktree` 隔离每一项任务。

## 基础概念：
1. 项目，达成目的的聚类行为概念。
2. worktree,隔离的工作区。
3. 步骤：实施规划的最小单元。

## 关键业务模块

# 项目创建：(done)
> 模块用途: 快速初始化项目并输出项目简介文件
操作流程：
    - 指定目录
    - 设置项目名称，描述
    - 创建，初始化一个git仓库，并根据"描述，项目名称"扩写填入生成项目第一个"README.md"文件。

功能拆分：
| 功能 | 说明 |
|------|------|
| 目录选择 | 指定项目创建的目标目录路径 |
| 项目信息录入 | 设置项目名称、描述等基本信息 |
| Git 仓库初始化 | 在目标目录中初始化 Git 仓库 |
| README 生成 | 基于项目名称和描述，由 AI 扩写生成初始 README.md |

# 项目管理：(done)
> 模块用途：项目的总览与导航入口，管理已有项目的生命周期，提供各功能模块的快速访问
操作流程：
    - 查看项目列表
    - 进入选定项目，查看项目概况与步骤进展
    - 快速跳转至 AI讨论聊天窗、任务呈现等子模块
    - 管理项目状态（进行中、已完成、归档等）

功能拆分：
| 功能 | 说明 |
|------|------|
| 项目列表展示 | 展示用户所有项目及其基本信息（名称、状态、创建时间） |
| 项目概况仪表盘 | 展示选定项目的整体进展、步骤统计、最近活动 |
| 模块导航 | 提供从项目维度快速跳转至聊天窗、步骤图谱等子功能 |
| 项目状态管理 | 支持项目状态流转：进行中 → 已完成 → 归档 |
| 项目配置 | 编辑项目基本信息、关联仓库路径等配置项 |

# AI讨论聊天窗：
> 模块用途：与AI讨论推进执行的窗口，并输出待执行步骤，讨论聊天窗口，与AI互动的主要交互区域。
操作流程：
    - 通过[AI任务实施引擎](#AI任务实施引擎：) 提供 AI 能力
    - 划区或选取指定内容，也可以不选取，手动输入。
    - 总结任务。
    - 创建并给出步骤依赖路线。

功能拆分：
| 功能 | 说明 |
|------|------|
| AI 对话交互 | 与 AI 进行多轮对话，讨论步骤细节 |
| 内容选取 | 支持划区或选取指定内容作为讨论上下文 |
| 手动输入 | 支持用户手动输入指令或需求描述 |
| 任务总结 | AI 自动总结讨论中的任务 |
| 步骤路线生成 | AI 创建并输出步骤及依赖关系 |

# 任务呈现：
> 模块用途：呈现AI讨论聊天窗口输出的，步骤实施路线图谱，可以人为调整或者补充
操作流程：
    - 查看步骤实施图谱
    - 编辑步骤实施内容
    - 呈现步骤当前实施状态

功能拆分：
| 功能 | 说明 |
|------|------|
| 步骤图谱展示 | 以图谱形式呈现步骤的实施路线 |
| 步骤编辑 | 支持人为编辑、调整步骤的内容 |
| 步骤状态追踪 | 实时展示每个步骤的当前实施状态 |


# AI任务实施引擎：
> 模块用途：配置，管理Agent，记录 worktree 管理完成提交流程等，保障任务实施可靠性，用户不可直接操作

功能拆分：
| 功能 | 说明 |
|------|------|
| Agent 配置管理 | 配置和管理 AI Agent 的参数与行为 |
| Worktree 管理 | 通过 Git Worktree 隔离各步骤的工作区 |
| 步骤执行调度 | 按依赖关系调度和执行步骤 |
| 提交流程管理 | 管理步骤的提交、合并流程 |
| 执行可靠性保障 | 记录日志、异常处理，保障步骤实施过程可靠 |


# AI实施引擎状态面板：
> 模块用途：呈现AI实施引擎当前运行状态，提供连接诊断与配置入口
操作流程：
    - 实时检测引擎服务可用性（健康检查）
    - 展示引擎连接状态（已连接 / 连接中 / 已断开 / 异常）
    - 配置引擎服务端点地址（Base URL）
    - 查看引擎版本与响应状态

功能拆分：
| 功能 | 说明 |
|------|------|
| 连接状态指示 | 顶部状态栏实时显示引擎连接状态，支持颜色区分 |
| 健康检查 | 定时轮询 `GET /global/health` 检测引擎服务可用性 |
| 引擎配置 | 弹出配置面板，设置/修改 OpenCode 引擎的 Base URL |
| 状态同步 | 配置保存后自动触发健康检查，即时反馈连接结果 |
| 异常提示 | 连接失败时提供明确错误信息，引导用户检查配置 |


## 模块实施原则

1. **模块解耦优先**：各模块之间通过明确的接口（Interface / Protocol）通信，不直接依赖内部实现。
2. **AI任务实施引擎可替换**：在 AI任务实施引擎 未完成前，其它模块通过 Mock / Stub 方式提供模拟的 AI 能力，确保前端交互与业务流程可独立开发、测试。
3. **依赖倒置**：项目创建、AI讨论聊天窗、任务呈现 等模块依赖的是 AI能力抽象接口，而非具体的引擎实现，引擎实现可随时替换。
4. **并行开发友好**：每个模块拥有独立的开发目录和测试用例，可各自推进，不因上游模块未就绪而阻塞。
5. **渐进集成**：引擎完成后，通过接入真实实现替换 Mock，无需修改其它模块的业务代码。
